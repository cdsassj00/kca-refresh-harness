# KCA 연구보고서 재검증 하네스 — 설계안

## 1. 왜 이 구조인가

발주 지시문의 요구는 "기존 연구보고서에 최신 자료를 덧붙이는 것이 아니라, **과거에 수행한 연구를 현재 시점에서 다시 수행한다면 어떤 결과가 도출될 것인가**"이다. 이를 한 건씩 수작업으로 하면 시연은 되지만 사업은 되지 않는다. 어떤 보고서를 넣어도 같은 절차가 돌아가는 하네스가 필요하다.

### 1.1 설계를 바꾼 관찰

KCA 연구보고서 게시판 164건의 제목을 키워드로 분류해 보면 이렇게 나온다.

| 유형 | 건수 |
|---|---|
| C. 제도/법제개선 | 35 |
| D. 진흥/활성화전략 | 26 |
| A. 전망/수요예측 | 17 |
| E. 기술/측정연구 | 16 |
| B. 실태/통계조사 | 10 |
| F. 기관운영/사업기획 | 8 |
| **Z. 미분류** | **52** |

**미분류가 52건(32%), 복수 유형에 동시에 걸리는 제목이 31건(19%)이다.** 예를 들어 「KCA 중장기 경영전략 및 실행 방안 연구」는 전망·전략·기관운영 셋 모두에 해당하고, 「국제 OTT 산업 실태조사 및 국내 OTT 글로벌 진출 방안 연구」는 실태조사와 진흥전략이 한 보고서에 들어 있다.

여기서 나오는 결론: **"보고서 유형별 최신화 방법"이라는 접근은 절반이 실패한다.** 보고서 한 권 안에 성격이 전혀 다른 주장들이 섞여 있기 때문이다. 한 보고서 안에도 "2021년 가입자는 3,564만 명이다"(통계 인용), "2030년 시장은 12조 원이 될 것"(예측), "전파법 제58조의2에 따르면"(법령 현황), "응답자의 62%가 찬성"(설문 결과), "세 가지 제도 개선을 제안한다"(정책대안)가 공존한다. 이들은 재검증 방법이 각각 다르다. 통계는 값을 갈아끼우면 되지만, 예측은 실적과 대조해 백테스트해야 하고, 법령은 개정 이력을 추적해야 하며, 설문은 다시 받아야 하고, 정책대안은 그동안 채택됐는지를 확인해야 한다.

### 1.2 그래서 분류 단위를 내린다

```
[기존 발상]  보고서 → 유형 판정 → 유형별 최신화     ← 52건이 분류에서 탈락
[본 설계]    보고서 → 주장(claim) 단위로 분해 → 주장 유형별 최신화 → 재조립
```

보고서 유형은 "이 보고서가 담은 주장 유형의 분포"로 **사후에 자동 산출**된다. 사람이 읽기 위한 라벨일 뿐, 처리 경로를 결정하지 않는다. 처리 경로는 주장 단위로 결정된다. 이 방식이면 미분류 보고서가 원리적으로 존재하지 않는다.

## 2. 주장 유형(Claim Type) — 재검증의 최소 단위

8가지로 나눈다. 각 유형은 **최신화 방법, 필요한 데이터 소스, 산출 지표, 실패 모드**가 다르다.

| ID | 주장 유형 | 보고서 속 모습 | 재수행 방법 | 산출 지표 |
|---|---|---|---|---|
| **T1** | 시계열 사실 | "2021년 유료방송 가입자 3,564만 명" | 동일 통계의 최신 시점 값으로 교체 | 값 변화율, 추세 반전 여부 |
| **T2** | 예측·전망 | "2030년 시장규모 12조 원 전망" | ① 예측 기준연도 이후 실적과 **백테스트** ② 최신 데이터로 **재예측** | 예측 오차(MAPE), 재예측치, 신뢰구간 |
| **T3** | 모형 추정치 | 회귀계수, CVM 지불의사액, 후생효과 O억 원 | 원 모형의 함수형태를 복원해 최신 데이터로 **재실행** | 계수 변화, 추정치 변화, 모형 적합도 |
| **T4** | 제도·법령 현황 | "현행 전파법 제58조의2는…" | 국가법령정보센터 **개정 이력 대조** | 조문 신설/개정/삭제 건수, 전제 붕괴 여부 |
| **T5** | 설문·조사 결과 | "응답자 62%가 찬성" | ① 원 설문지 복원 → **개정판 설계** ② 합성응답 시뮬레이션(참고용) | 문항 유효성 판정, 모의 응답분포 |
| **T6** | 정책대안·제언 | "세 가지 제도 개선을 제안한다" | 제언 이후 **채택 여부 추적**(법령·정책·예산·조직) 후 유효성 재평가 | 채택/부분채택/미채택/무효화 |
| **T7** | 시장구조·사업자 사실 | "웨이브와 티빙은 별도 사업자" | 기업 사건(M&A, 진입·퇴출, 서비스 종료) 추적 | 사실 유효/무효, 사건 목록 |
| **T8** | 기술·표준 규격 | "3GPP Rel-16 기준으로" | 표준화 기구 최신 릴리스 대조 | 세대 격차, 폐기 여부 |

### 2.1 주장마다 붙는 판정(verdict)

재검증의 결론은 다섯 중 하나로 라벨링한다. 이게 최종 보고서의 뼈대가 된다.

- **유지(HOLD)** — 지금 다시 해도 같은 결론. 근거 데이터도 방향이 같다.
- **수치조정(REVISE)** — 결론 방향은 맞으나 숫자가 달라짐. 새 값 제시.
- **반전(REVERSE)** — 결론이 뒤집힘. 당시 전망과 반대 방향으로 전개됨.
- **무효(OBSOLETE)** — 전제가 사라져 주장 자체가 성립하지 않음(법 폐지, 사업자 소멸, 기술 단종).
- **판정불가(UNRESOLVED)** — 검증할 최신 데이터를 확보하지 못함. **모른다고 적는다.**

마지막 항목이 중요하다. 근거를 못 찾았을 때 그럴듯하게 지어내는 것이 이런 작업의 가장 큰 실패 모드다. 하네스는 출처 URL·발행처·기준시점이 없는 주장은 자동으로 UNRESOLVED로 강등한다.

## 3. 파이프라인 7단계

```
 [입력] 연구보고서 PDF (+ 메타데이터)
   │
   ├─ 1. INGEST     PDF → 구조화 텍스트 (장/절/표/각주/부록 보존)
   ├─ 2. PROFILE    주장 추출 → 유형 태깅 → 보고서 프로파일 자동 산출
   ├─ 3. PLAN       재검증 실행계획 수립 (주장별 필요 데이터 소스 매핑)
   ├─ 4. REFRESH    최신 데이터 수집 (통계 API + 웹 딥리서치 + 법령 이력)
   ├─ 5. SIMULATE   재추정·백테스트·설문 재설계·합성응답
   ├─ 6. ADJUDICATE 주장별 판정 + 근거 + 신뢰도 등급
   └─ 7. RENDER     산출물 생성 (대조표 / 한글보고서 / 시연덱 / JSON)
```

각 단계의 경계는 **파일**이다. 중간 산출물이 모두 디스크에 남으므로 특정 단계만 다시 돌릴 수 있고, 시연 중에 "여기서 이게 나왔습니다" 하고 열어 보일 수 있다.

### 단계별 상세

**1. INGEST** — PDF에서 텍스트·표·페이지 번호를 뽑되, **장절 구조와 페이지를 반드시 유지**한다. 나중에 모든 주장에 "원문 p.47" 출처를 달아야 하기 때문이다. 스캔본이면 OCR로 분기한다. 부록(설문지·조사표)은 별도 플래그를 세워 T5 처리로 보낸다.

**2. PROFILE** — 문서를 훑어 주장 후보를 뽑는다. 숫자+연도 패턴, "전망/예측/추정된다", "제안한다/필요하다", "제O조", "응답자/설문/조사결과" 같은 신호로 1차 후보를 걸러낸 뒤 LLM이 유형을 판정하고 정규화한다. 산출은 `claims.jsonl` — 주장 텍스트, 유형, 원문 위치, 숫자값, 단위, 기준연도, 목표연도.

동시에 보고서 프로파일이 나온다. 예: `{T1:34, T2:12, T3:5, T4:2, T5:0, T6:9, T7:7, T8:1}` → "전망·예측형 보고서, 설문 없음, 모형 재실행 필요".

**3. PLAN** — 주장 유형별 플레이북(§4)을 적용해 실행계획을 만든다. "이 12개 T2 주장을 검증하려면 과기정통부 무선통신서비스 가입현황 월별 통계와 방송산업실태조사 2025년판이 필요하다"는 식의 **데이터 요구 목록**이 나온다. 여기서 확보 불가능한 것이 식별되면 미리 UNRESOLVED 예정으로 표시한다.

**4. REFRESH** — 세 경로로 수집한다.
- **정형 통계**: KOSIS·공공데이터포털·과기정통부 통계 API (가능한 것은 코드로 자동 수집, 캐시)
- **비정형 최신 동향**: 웹 딥리서치 (사건·발표·업계 변화). 반드시 URL·발행일·발행처를 함께 저장
- **법령 이력**: 국가법령정보센터에서 해당 법령의 개정 연혁과 현행 조문

수집물은 `evidence/` 에 원본 그대로 저장한다. 나중에 "이 숫자 어디서 났냐"는 질문에 답해야 한다.

**5. SIMULATE** — 유형별로 갈린다.
- T2: 예측 기준연도 이후 실적을 붙여 **백테스트 그래프**를 그리고, 오차를 계산한 뒤 최신 데이터로 재예측
- T3: 원 모형의 함수형태·변수·데이터 기간을 보고서에서 복원해 최신 데이터로 재실행. 복원 불가면 "모형 재현 불가, 대체 추정" 으로 명시
- T5: 원 설문지 복원 → 문항별 현행 유효성 판정(그대로/수정/삭제/신설) → 개정 설문지 초안 + 표본설계 + 합성응답 시뮬레이션

**6. ADJUDICATE** — 주장별로 5단계 판정을 내린다. 이때 **판정 근거와 반대 근거를 함께 적는다.** 그리고 신뢰도 등급(A: 공식통계 대조 / B: 업계자료 / C: 단일 언론보도 / D: 추론)을 붙인다.

**7. RENDER** — 아래 네 가지를 생성한다.
- `대조표.md` — 원문 문장 ↔ 현행화 문장 나란히 (연구진이 실제로 보고서를 고칠 때 쓰는 실무 산출물)
- `재검증보고서.hwpx` — 기관 제출용 한글 문서
- `시연덱.html` — 1280×720 발표 슬라이드 (Before/After, 빗나간 전망 하이라이트)
- `claims.json` — 기계가 읽는 구조화 데이터 (보고서 간 누적 비교·대시보드 확장용)

## 4. 유형별 최신화 플레이북 (`profiles/*.yaml`)

하네스의 "설정 가능한 부분"이 여기다. 새 유형이 나오면 YAML 한 장을 추가하면 된다.

```yaml
# profiles/T2_forecast.yaml  (예측·전망)
claim_type: T2
detect:
  cues: ["전망", "예측", "추정된다", "이를 것으로", "달할 것"]
  require: [숫자, 목표연도]
refresh:
  sources: [kosis, msit_wireless_stats, industry_survey, deep_research]
  must_have_citation: true
simulate:
  backtest:
    method: 예측 기준연도 이후 실적 시계열 대조
    outputs: [절대오차, MAPE, 추세방향_일치여부]
  reforecast:
    method: [단순추세연장, CAGR재산정, 최신_3rd파티_전망_인용]
    require_interval: true          # 점추정 금지, 구간으로
adjudicate:
  REVERSE_if: 실적_추세방향이_전망과_반대
  OBSOLETE_if: 예측대상_서비스_또는_시장_소멸
render:
  chart: 전망_vs_실적_라인차트
```

8개 유형 각각에 대해 같은 형식의 YAML을 둔다. 코드는 YAML을 읽어 동작하므로, **처리 규칙을 바꾸려고 파이썬을 고칠 일이 없다.**

### 특히 까다로운 두 유형

**T5(설문·조사) — 설문을 다시 받아야 하는 상황**

원 보고서에 설문지가 부록으로 실려 있으면 문항을 파싱해 표로 만들고, 문항별로 네 가지 판정을 내린다.

| 판정 | 조건 | 예시 |
|---|---|---|
| 그대로 유지 | 개념·선택지가 지금도 유효 | "귀하의 연령대는?" |
| 선택지 수정 | 보기가 현실과 어긋남 | "주 이용 OTT" 보기에 웨이브·티빙 별도 표기 → 합병 반영 |
| 문항 삭제 | 대상이 소멸 | "DMB 이용 빈도" |
| 문항 신설 | 새 현상 미포착 | "생성형 AI 기반 콘텐츠 추천 이용 경험" |

그 위에 **합성응답 시뮬레이션**을 얹는다. 최신 이용행태 통계(방송매체이용행태조사 등)로 인구·이용 분포를 보정한 가상 응답을 생성해 "지금 조사하면 대략 이렇게 나올 것"을 보여준다. 단, 산출물 모든 페이지에 **"AI 모의추정치이며 실조사를 대체하지 않음"** 을 명시하고, 실조사 설계서(표본·예산·기간)를 함께 낸다. 이게 없으면 시연은 화려하지만 학술적으로 방어가 안 된다.

**T6(정책대안) — 제언이 채택됐는지 추적**

정책 제언은 "맞았나/틀렸나"가 아니라 "**반영됐나**"로 검증한다. 제언 이후의 법령 개정, 정부 기본계획, 예산사업, 조직개편을 뒤져 채택 여부를 판정하고, 미채택이면 지금도 유효한지 아니면 상황이 변해 무의미해졌는지를 재평가한다. 이 유형이 발주처 입장에서 가장 반응이 좋을 부분이다. "우리가 2021년에 제안한 것 중 넷이 실제 정책이 됐고, 둘은 상황이 변해 폐기 대상"이라는 표는 기관 성과 자료로도 쓰인다.

## 5. 폴더 구조

```
kca-revalidate/
├─ SKILL.md                    클로드가 읽는 절차서 (하네스 진입점)
```

## 7. 품질 관리 — 이 작업의 진짜 위험

이 하네스의 실패는 "안 돌아감"이 아니라 "**그럴듯한 거짓을 자신 있게 출력함**"으로 온다. 재검증 보고서는 숫자와 출처가 생명인데, LLM은 둘 다 지어낼 수 있다. 세 가지 방어선을 건다.

1. **출처 없는 주장은 자동 강등** — 모든 최신 값에 URL·발행처·기준시점 필수. 없으면 UNRESOLVED로 내리고 보고서에 "확인 필요"로 표기한다.
2. **원문 대조 강제** — 모든 "당시 주장"에 원문 페이지 번호를 달고, 렌더링 시 원문 텍스트를 그대로 인용한다. 요약하지 않는다.
3. **분리 검증 패스** — 산출된 판정을 작성한 것과 **다른 세션/에이전트**가 다시 검사한다. 특히 REVERSE·OBSOLETE 판정은 근거가 충분한지 별도로 확인한다. 자기가 쓴 걸 자기가 승인하지 않는다.

추가로, 합성응답·재예측치에는 반드시 신뢰구간과 "모의추정" 표기를 붙인다.

## 8. 검증 방법

하네스가 제대로 동작하는지는 이렇게 확인한다.

- **정답지 대조**: 2단계에서 만든 수동 재검증 결과와 자동 결과의 주장별 판정 일치율. 80% 이상이면 실용 수준.
- **역방향 테스트**: 2019년 보고서에 대해 "2022년 시점 재검증"을 돌려, 실제 2022년에 알려진 사실과 맞는지 확인한다. 미래를 맞히는지가 아니라 과거를 재현하는지를 본다.
- **출처 추적성**: 최종 보고서의 모든 숫자를 무작위로 10개 뽑아 `evidence/` 원본까지 역추적되는지 확인.
- **범용성**: 성격이 다른 보고서 3편(전망형·법제형·실태조사형)을 넣어 모두 오류 없이 7단계를 통과하는지.
