# KCA 연구보고서 결론 재도출 하네스 — 구성과 기술 스펙 설명서

- 작성일: 2026-09-15
- 읽는 사람: 이 도구를 넘겨받는 기관의 관리자(비전공)와 실무자(설치·실행 담당). 1~4절은 관리자용, 5~6절은 실무자용, 7~8절은 둘 다.
- 함께 볼 문서: 쉬운 설명 `docs/하네스_구조_쉬운설명.md` · 폴더 묶음 `docs/폴더_구성.md` · 설계서 `docs/superpowers/specs/2026-09-15-kca-refresh-harness-design.md` · 독립 프로그램 설계·계약 `app/DESIGN.md` · 키 발급 안내 `docs/api_keys_guide.md` · 규칙 `CLAUDE.md`
- 이 문서의 숫자 예시는 모두 첫 샘플 R01(「디지털전환에 따른 5G 모바일 시장전망 및 주파수 경제성 분석」, 2023-04 발간, 140쪽)의 실제 실행 결과 파일(`reports/R01/`)에서 가져왔다.

---

## 1. 한 장 요약

옛 연구보고서를 넣으면, 정해진 규칙과 절차 안에서 움직이는 AI 조사팀이 발간 이후 바뀐 사건을 찾고, 결론을 떠받치던 숫자를 오늘 값으로 바꿔 보고, 결론마다 「지금 다시 연구해도 같은 결론이 나오는가」에 도장을 찍어 신구 대조표로 내준다.
**새 보고서를 대신 써 주는 도구가 아니다. 어느 결론을 다시 연구해야 하는지 가려내는 도구다.** 자료를 최신으로 바꾸는 일은 입력이고, 결론별 판정(동일·부분수정·약화·뒤집힘 등)과 다음 조치(유지·부록 갱신·재연구 발주 등)가 산출물이다.
R01 샘플에서는 결론 16건 중 2건이 그대로 유효(동일), 7건이 손질 필요(부분수정 5·약화 2), 2건은 실측 없이는 판정할 수 없어 설계서를 붙였고(판정불가), 원 연구에 없던 결론 4건이 새로 나왔다.

> **하네스**(harness): 원래는 말에 씌우는 마구. 여기서는 "AI가 정해진 절차와 규칙 밖으로 나가지 못하게 잡아 주는 틀"이라는 뜻이다.

## 2. 동작 원리 (쉬운 판)

보고서 한 편은 세 단계를 지난다. 단계마다 R01에서 실제로 나온 결과를 한 줄씩 붙였다.

| 단계 | 하는 일 | 결과물 | R01 실제 예 |
|---|---|---|---|
| **① 바뀐 것 찾기** (L0) | 발간일 이후 그 분야에서 일어난 정책·기술·시장 사건을 출처와 함께 날짜순으로 모은다. 사건이 어느 전제를 흔드는지 따라가 결론마다 **잠정** 판정을 낸다. 어떤 보고서든 여기까지는 바로 된다. | `L0/environment_delta.md`(사건 표), `L0/events.json`, `L0/provisional_verdicts.json` | 발간(2023-04) 이후 사건 15건. 예: 2023-05-31 SKT 28㎓ 할당취소로 이통3사 모두 28㎓ 철수, 2024-07-31 제4이통(스테이지엑스) 선정 취소 → "주요국처럼 24~28㎓ 광대역을 쓴다"는 전제가 국내에서 사라짐. 결론 12건에 잠정 판정(유지 가능성 높음 3·중간 9). |
| **② 숫자 다시 맞춰보기** (L1) | 결론을 떠받치던 수치를 실적·최신 조사·재계산으로 갱신한다. 전망은 실적과 비교하고, 제언은 채택·입법 여부를 추적한다. 실적을 못 찾으면 "검증불가"로 두고 어디까지 찾았는지 적는다. | `L1/verdicts.json` | 이음5G 누적 구축 26곳(2022) → 54곳(2023) → 74곳(2024) → 104곳(2025). 원문의 2025년 중간 시나리오 93곳 대비 오차 약 -10.6% → 시나리오 범위 안이므로 "적중". 근거 15건 중 4건(결론 단위로는 7건 중 2건)은 사이트당 설비투자비 같은 공개 실적이 없어 검증불가. |
| **③ 결론 다시 내보기** (L2) | 결론을 두 번 다시 낸다. (가) 원 방법에 오늘 값을 넣어 **추적 재도출**, (나) 원문을 전혀 보지 않은 AI가 연구질문과 방법만 받아 **블라인드 재수행**. 원 결론까지 셋을 나란히 놓고 최종 판정과 다음 조치를 붙인다. | `L2/traced/`, `L2/blind_output/`, `comparison_table.json` → `07_report/comparison_table.html` | 추적 재도출 4건·블라인드 6문항. 대조표 결론 16행: 동일 2·부분수정 5·약화 2·신규결론 4·판정불가 2·잠정 1. 예: 주파수 정책 제언(R-02)은 28㎓ 취소와 "2차 공유면허" 미입법으로 **부분수정 → 재연구 발주**. 2030년 사이트 전망(Fc-06)은 원문 중간 910곳 vs 블라인드 중간 479곳으로 **약화**. |

> **블라인드 재수행**: 원 결론을 모르는 AI에게 연구질문·방법·오늘의 환경 요약만 주고 결론을 내게 하는 것. 원 결론에 끌려가는 것(앵커링)을 막는다.
> **추적 재도출**: 원 보고서가 쓴 계산 방법을 바꾸지 않고, 입력값만 오늘 값으로 바꿔 다시 계산하는 것.
> **논증 사슬**: 결론 ← 방법 ← 전제(환경분석의 사실·가정) + 근거(표·수치·조사)의 연결. ①~③은 모두 이 사슬을 따라 움직인다.

세 단계 앞에는 준비 작업 세 가지가 있다. **접수**(PDF를 글자로 바꿈) → **분류**(분야와 유형 표시) → **결론 찾기**(결론 8~12개와 논증 사슬 추출). R01은 분야 `spectrum`·`network_5g6g`, 유형은 전망 40%·경제성 20%·사례 20%·정책 10%·기술 10%로 분류됐다.

말로 할 때는 이렇게 줄인다. **"바뀐 것을 찾고, 숫자를 다시 맞춰보고, 결론을 다시 내서 대조표로 냅니다."**

## 3. 실행 방식 두 가지

같은 규칙(사규)·절차서·자료실·계산기를 두 가지 방법으로 돌릴 수 있다. 하나만 있어도 되고, 둘을 같이 두어도 된다. **독립 프로그램을 기본으로 권장**한다.

| | **독립 프로그램** (권장) | **Claude Code 하네스** |
|---|---|---|
| 한 줄 | 브라우저 화면에서 접수·실행·열람. AI 호출은 OpenRouter(OpenAI 호환 API) | Claude Code 터미널에서 `/refresh-run`. AI 호출은 Claude Code 가 서브에이전트로 |
| 필요한 것 | Python 3.11, **OpenRouter API 키**(종량제, 선불 크레딧) | Python 3.11, Node.js, **Claude Code 로그인**(구독 또는 기관 발급 키) |
| 모델 | OpenRouter 에 있는 어떤 모델이든 선택. 특정 제공사·사내 서버(OpenAI 호환)로 직접 연결도 가능(`LLM_BASE_URL`) | Claude |
| 입력 | PDF · HWPX · DOCX · TXT (HWP 는 `pyhwp` 선택 설치) | PDF |
| 화면 | 대시보드·접수·실행·결론 대조표·영향 지도·산출물·지식베이스·설정 8개 | 없음(터미널). 결과는 HTML 파일로 열람 |
| 시작 | `app\run_app.bat` → `http://127.0.0.1:8765` | `setup.bat` → `/refresh-run R01` |
| 데이터 경로 | 내 PC → OpenRouter → 선택한 모델 제공사 | 내 PC → Anthropic |
| 산출물 | `reports/<ID>/` (같은 구조·같은 파일명) | `reports/<ID>/` (같음) |
| 문서 | `app/SETUP.md`, `app/README.md` | `SETUP.md`, `AGENTS.md` |

둘이 공유하는 것(공통 핵심): `prompts/`(절차서 원본), `templates/`(규칙·스키마), `kb/`(자료실), `scripts/`(계산기), `reports/`·`registry.csv`(서류함·현황판). 어느 쪽으로 돌려도 같은 자리에 같은 파일이 남으므로 서로 열어 볼 수 있다. 파일별 소속은 `docs/폴더_구성.md`.

독립 프로그램이 절차서를 쓰는 방식: 단계마다 `prompts/NN.md` **전문**과 입력 파일을 LLM 에 보내고, LLM 이 검색·열람 도구를 부르면 프로그램이 대신 실행해 결과를 돌려주며, 최종 JSON 을 스키마로 검사해 서랍에 쓴다. 블라인드 단계는 브리프만 넣고 파일 읽기 도구를 빼서 격리한다. 즉 **"누가 AI 를 부르느냐"만 다르고 규칙·절차·검사는 같다.**

## 4. 구성 (사무실 비유 → 실제 폴더)

비유는 하나만 쓴다. **"AI 조사팀이 일하는 사무실."** 사무실에는 사규, 절차서, 직원, 계산기, 자료실, 서류함, 접수창구가 있다.

| 사무실 | 실제 파일·폴더 | 무엇인가 | 현재 상태 |
|---|---|---|---|
| **규칙(사규)** | `CLAUDE.md` | 항상 지켜야 하는 규칙. 출처 없는 숫자 금지, 작성자와 검토자 분리, 원문 안 본 AI에게 원문 주지 않기, 설문·실험을 한 척하지 않기, 원 결론 문장은 절대 고치지 않기, 키는 `.env`에만 | 있음 |
| **절차서** | `prompts/*.md`(원본 9장: 00 접수·분류 … 08 검토), `.claude/skills/`(Claude Code용 포장 5개: refresh-run 총괄, refresh-l0, refresh-verify, refresh-rederive, refresh-report) | 단계마다 "무엇을 읽고, 무엇을 남기고, 무엇을 하면 안 되는가"를 적은 문서. 도구에 종속되지 않는 마크다운 원본이 `prompts/`이고, `.claude/skills/`는 그것을 Claude Code 명령(`/refresh-run` 등)으로 감싼 것. 독립 프로그램(`app/engine/stages.py`)은 `prompts/` 원본을 직접 읽는다. 다른 도구용 안내는 `AGENTS.md` | 있음 |
| **역할 카드** | `.claude/agents/` (11개) | AI 직원 11명의 역할 지시문. 조사 4(사건·문헌·정책·영향 전파), 계산 4(전망 검증·모형 재구성·재설문 설계·재실험 계획), 판정 2(블라인드 재수행·비교), 검토 1(비평). 사람이 아니라 AI에게 주는 업무분장표다 | 있음. R01은 이 중 6개 역할로 실행됨 |
| **계산기·검사기** | `scripts/` | 누가 다시 돌려도 같은 답이 나와야 하는 일은 AI가 아니라 프로그램이 한다. 접수(`intake.py`), 근거 수집·소스 점검(`evidence.py`), 형식 검사(`validate.py`), 현황판(`registry.py`), 대조표 HTML(`render_table.py`), 현행화 보고서 Markdown·HTML(`render_report.py`). 자동 테스트 34개(`tests/`) | 있음 |
| **자료실** | 바깥: 논문·통계·법령·뉴스 API(열쇠는 `.env`) / 안쪽: `kb/` | 바깥 자료실에서 근거를 가져오고, 한 번 찾은 사건(`kb/events/`)과 근거(`kb/evidence/`)는 안쪽에 쌓아 다음 보고서가 다시 쓴다. 조회 결과는 `kb/cache/`에 7일간 보관해 같은 질의를 다시 부르지 않는다 | 키 없는 커넥터 4종(OpenAlex·Crossref·Semantic Scholar·arXiv) 있음. 키 필요한 22종은 카탈로그에 등록되어 `doctor`가 키 유무를 보여주며 커넥터는 다음 단계 |
| **서류함·현황판** | `reports/<보고서번호>/`, `registry.csv` | 보고서마다 서랍 하나. 서랍 안은 `00_source/`(원문 글자), `01_meta.json`, `02_classification.json`, `03_argument_chains.json`, `L0/`, `L1/`, `L2/`, `comparison_table.json`, `07_report/`, `logs/`. 현황판에는 보고서별 발간 연월, 경과 연수, 몇 층(L0~L3)까지 갔는지 적힌다 | 있음. `reports/R01/` L2(부분), 샘플 7편 등록 |
| **접수창구** | `app/` (독립 프로그램: `server/`+`ui/` 브라우저 화면) | 보고서를 고르고, 어디까지 할지와 옵션을 켜고, 실행 버튼을 누르고, 결과를 열어 보는 화면 8개(대시보드·접수·실행·결론 대조표·영향 지도·산출물·지식베이스·설정). 뒤에서는 `app/engine`이 절차서를 OpenRouter 로 보내 돌린다 | 있음(독립 프로그램). Claude Code 방식은 창구 없이 터미널 `/refresh-run`으로 실행하고 결과 HTML을 연다 |

그 밖의 폴더: `templates/`(분류체계·판정 규칙·스키마·양식), `samples/pdf/`(공개 샘플 보고서 7편), `tests/`(자동 테스트), `docs/`(설명서), `runs/`(실행 기록).

말로 할 때는 이렇게 줄인다. **"규칙, 절차서, 역할 카드, 계산기, 자료실, 서류함, 접수창구. 이 일곱 개가 전부입니다."**

## 5. 기술 스펙

| 항목 | 내용 |
|---|---|
| **실행 환경** | 두 방식(3절). **독립 프로그램**: Python 3.11 이상 + OpenRouter API 키(또는 OpenAI 호환 엔드포인트). `app\run_app.bat`이 가상환경·패키지·서버(`127.0.0.1:8765`)를 준비하고 브라우저를 연다. Claude Code 불필요. **Claude Code 하네스**: Claude Code CLI 2.1 이상(설계 시 2.1.x로 확인) + Python 3.11. 둘 다 Windows 우선(경로·PowerShell 기준으로 작성·검증). macOS/Linux는 `run_app.sh`·`setup.sh`로 동작하나 미검증 |
| **권한 설정** (Claude Code 방식) | `.claude/settings.json`에 스크립트 실행(`python scripts/*`), 파일 읽기·쓰기, 웹 검색·열람, 서브에이전트 호출을 미리 허용해 두어 실행 중 매번 묻지 않는다. 독립 프로그램은 해당 없음 |
| **언어·패키지** | Python 3.11 이상. 공통: `requests`(HTTP 수집), `jsonschema`(산출물 형식 검사), `PyYAML`(규칙 파일 읽기), `python-dotenv`(`.env` 읽기), `defusedxml`(외부 XML 안전 파싱), `pypdf`(PDF 글자 추출), `markitdown`(각종 문서→Markdown 변환), `pytest`(테스트). 설치는 `python -m pip install -r requirements.txt`. 독립 프로그램은 여기에 `fastapi`·`uvicorn`(웹 서버), `httpx`(API 호출), `trafilatura`·`beautifulsoup4`(웹 본문 추출)을 더한다(`app/requirements.txt`, `run_app.bat`이 자동 설치). HWP 직접 접수는 `pyhwp` 선택 설치 |

OpenRouter는 계정 설정(Privacy)에서 학습·로그 허용 여부를 정할 수 있고, 특정 제공사와 직접 계약한 API나 사내 서버로 바꾸려면 [설정]의 `LLM_BASE_URL`을 그 OpenAI 호환 주소로 바꾼다. 외부로 나가는 것은 원문 글자와 검색어이며, `app/.env`·`.env`의 키 값은 프로그램 안에서만 쓰이고 산출물·로그에 기록되지 않는다.

## 8. 자주 묻는 질문

**Q1. AI가 숫자를 지어내면 어떡하나?**
출처 URL이 없는 숫자는 검사기가 거부한다. 모든 숫자에 A(공식)·B(언론·업계)·C(추정·시뮬레이션) 등급이 붙고, 실적을 못 찾으면 추정하지 않고 "검증불가"로 둔다. R01 대조표의 모든 행에는 근거 링크가 달려 있어 사람이 눌러 확인할 수 있다.

**Q2. 설문을 다시 해야 하는 결론은?**
"판정불가"로 두고 재설문 설계서를 붙인다. AI가 응답을 만들어 채우지 않는다. 그 결론은 사람이 재조사를 발주할지 결정하는 목록에 올라간다.

**Q3. Claude Code가 꼭 필요한가?**
아니다. 독립 프로그램(`app/`)은 같은 절차서를 OpenRouter(OpenAI 호환 API)로 돌리므로 Claude 구독 없이 어떤 모델이든 쓸 수 있고, 이쪽을 기본으로 권장한다. Claude Code 방식은 이미 그 도구를 쓰는 사람에게 맞다. 절차서와 역할 카드를 파일로 두는 방식을 그대로 지원하고, 무엇을 읽고 어떤 근거로 판정했는지 과정이 파일과 로그로 남는다. 절차서 원본(`prompts/`)은 도구에 묶여 있지 않아 두 방식이 같은 파일을 읽는다.

**Q4. 비용과 시간은?**
독립 프로그램은 종량제다. 토큰 수 × 모델 단가로 OpenRouter 선불 크레딧에서 빠지며, 실행 화면에 누계가 보인다. 키에 월 한도를 걸어 두고, 처음은 L0만 돌려 실제 비용을 본 뒤 결정한다. Claude Code 방식은 보고서 한 편에 서브에이전트 6~10회가 든다. 어느 쪽이든 결론 수에 비례하며, 블라인드 재수행(결론당 1회)이 가장 큰 몫이다. 블라인드를 끄거나 L0(바뀐 것 찾기)까지만 돌리면 크게 줄어든다. 외부 API는 대부분 무료 한도 안에서 쓴다.

**Q5. 다른 보고서도 되나?**
된다. 서랍(`reports/R08/`) 하나 더 만들고 접수·실행하면 같은 길을 간다. 규칙·절차서·자료실이 보고서 바깥에 있어서 보고서를 바꿔도 손댈 것이 없다. 분야가 새로우면 `kb/`에 사건이 쌓이기 전이라 첫 실행이 더 오래 걸린다.

**Q6. 지금 어디까지 됐나?**
샘플 보고서 7편 확보, 설계 확정, 절차서 원본 9장, Claude Code 스킬 5개와 역할 카드 11개, 계산기·검사기 6종과 자동 테스트 34개, 키 없는 근거 커넥터 4종과 소스 상태 점검(`doctor`), 현황판, 설치 스크립트와 설정 체크리스트(`SETUP.md`)까지 완성. 첫 샘플 R01은 세 단계를 모두 지나 `L2(부분)` 대조표(결론 16행·본문 8행)와 현행화 보고서(Markdown·HTML)까지 나왔다. 여기에 Claude Code 없이 OpenRouter 키 하나로 도는 독립 프로그램(`app/`: 브라우저 화면 8개, PDF·HWPX·DOCX 접수, 실행·열람·키 설정)이 더해졌다. 키가 필요한 국내 통계·법령·뉴스 커넥터, HWPX 출력, L3 설계서 자동 첨부는 다음 단계다.
