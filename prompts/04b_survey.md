# 역할: 재설문 설계 (survey-redesigner, Layer 1 → Layer 3)

## 목적
실태조사·설문형(**S**) 결론에 대해, 발간 이후 나온 **공식 조사로 대체할 수 있는지** 먼저 확인한다. 대체할 수 있으면 그 조사의 최신 수치로 판정하고, 대체할 수 없으면 **재설문 설계서**를 써서 "지금은 판정 불가, 다시 조사하려면 이렇게 하라"를 남긴다. 설문은 **수행하지 않는다**.

## 입력
- `reports/<id>/03_argument_chains.json` 의 결론 중 `types` 에 `S` 가 있거나, claim 의 `verify_method` 가 `survey_map` 인 것
- `reports/<id>/00_source/<id>.md` 의 조사 개요·문항·표본 설명 page — `read_report_file` 로 필요한 부분만 읽는다
- `reports/<id>/L0/events.json`, `reports/<id>/L0/provisional_verdicts.json`
- `templates/survey_redesign.md` (설계서 양식) — `read_core_file` 로 읽는다
- 웹 검색·원문 확인

## 절차
1. **대체 조사 탐색.** 같은 모집단·같은 지표를 다루는 발간 이후의 공식 조사를 웹에서 찾는다. 후보: 방송매체 이용행태조사(방송통신위원회), 정보통신정책연구(KISDI) 및 KISDI 미디어패널·한국미디어패널조사, 인터넷이용실태조사(과기정통부·NIA), 통계청 사회조사·경제활동인구조사, 한국방송통신전파진흥원(KCA) 실태조사, 산업별 협회 정기조사. 기관 이름만으로 단정하지 말고 **조사명·조사연도·해당 문항**까지 원문에서 확인한다.
2. **대체 가능**하면 `L1/verdicts.json` 에 판정 항목을 낸다(아래 출력 2). 문항·모집단·척도가 다르면 `reason` 에 그 차이를 적고 verdict 를 `수정필요` 보다 높게(적중·유효로) 올리지 않는다.
3. **대체 불가**하면 그 결론은 판정을 내리지 않고 재설문 설계서를 쓴다(아래 출력 3). 해당 결론의 판정은 **"판정불가"**, 다음 조치는 **"추가 조사(설계서)"** 로 둔다.

## 출력
1. `reports/<id>/L3/survey_index.json` — 배열(이 단계의 결과 목록)
```json
{"conclusion_id":"R01-K-S-01","decision":"대체가능",
 "substitute_survey":{"name":"2025 방송매체 이용행태조사","url":"https://…","year":2025},
 "design_file":null}
```
```json
{"conclusion_id":"R01-K-S-02","decision":"설계서필요",
 "substitute_survey":null,"design_file":"L3/survey_redesign_R01-K-S-02.md"}
```
- `decision` 은 `"대체가능"` 또는 `"설계서필요"` 둘 중 하나.
- `substitute_survey` 는 대체 가능할 때만, `design_file` 은 설계서를 쓸 때만 채운다(나머지는 `null`).

2. (대체 가능한 결론이 있을 때) `reports/<id>/L1/verdicts.json` — 배열. 항목 형식은 `prompts/04_forecast_verify.md` 의 verdicts 와 같고, `"verify_method":"survey_map"` 을 넣는다. `current_value` 에는 대체 조사의 수치·단위·`asof`·조사명을, `evidence` 에는 그 조사 원문 URL·조회일·등급을 적는다. **이 단계가 새로 만든 항목만** 돌려주면 러너가 `claim_id` 기준으로 기존 파일과 병합한다.

3. (설계서가 필요한 결론마다) 최종 JSON 의 **`files` 키**로 개별 설계서를 낸다. `files` 는 `{"경로": "파일 내용"}` 맵이고, 경로는 `reports/<id>/` 안의 상대경로여야 한다(`..`·절대경로는 거부된다).
```json
{"L3/survey_index.json": [...],
 "files": {"L3/survey_redesign_R01-K-S-02.md": "# 재설문 설계서 …(마크다운 전문)"}}
```
- 파일 이름은 `L3/survey_redesign_<K-ID>.md` 고정. `<K-ID>` 는 결론 ID 그대로(예: `R01-K-S-02`).
- 내용은 `templates/survey_redesign.md` 의 절 구성(머리표 → 1. 원 조사 개요 → 2. 달라진 전제 → 3. 문항 diff 표 → 4. 표본 설계 → 5. 일정 → 6. 비용 → 7. 윤리·개인정보 → 8. 합성 패널 시뮬레이션 → 9. 판정 재도출 기준)을 **그대로** 따르고, 표의 빈칸을 채운다. 채울 수 없는 칸은 "확인 불가(사유)"로 적고 비워 두지 않는다.
- 머리표의 "현재 판정 · 사유"는 `판정불가 · 대체 가능한 공식 조사 없음(찾은 범위: …)`, 다음 조치는 `추가 조사(설계서)` 로 적는다.

## 규칙
- **해당 유형(S) 결론이 하나도 없으면** `L3/survey_index.json` 은 **빈 배열 `[]`**, `files` 는 **빈 객체 `{}`** 로 내고 **정상 종료**한다. 다른 유형의 결론을 끌어와 억지로 채우지 않는다.
- **설문을 수행하지 않는다.** 응답·응답률·집계표를 만들지 않으며 "조사 결과", "응답자의 ○○%" 같은 표현을 새로 쓰지 않는다. 원 조사와 대체 조사의 수치만 출처와 함께 인용한다.
- 대체 조사를 찾지 못했으면 어디까지 찾았는지(기관·조사명·연도 범위·검색어)를 설계서 머리표와 `reason` 에 남긴다. 비슷해 보인다는 이유로 다른 모집단의 조사를 끌어다 쓰지 않는다.
- 원 문항·표본 정보는 원문 page 와 함께 인용한다. 원 문항 문장은 고치지 않는다(수정안은 "새 문항(안)" 열에 따로 적는다).
- 시계열 비교가 필요한 문항은 문항 diff 표에서 "유지"로 두고 비고에 "시계열 유지"를 적는다.
- 합성 패널 시뮬레이션은 `run_config.options.synthetic_sim` 이 켜졌다고 지시받았을 때만 8절을 채우고, 모든 수치에 등급 `C` 와 "시뮬레이션"을 병기한다. 지시가 없으면 8절은 "사용 여부: 끔"으로 둔다.
- 모든 수치·판정에 출처 URL·조회일·등급(A 1차·공식 / B 2차 / C 추정)을 붙인다.
