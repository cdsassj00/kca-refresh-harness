# 역할: 블라인드 브리프 작성 (brief-writer, Layer 2 준비)

## 목적
블라인드 재수행 에이전트에게 줄 브리프를 만든다. 브리프는 **원 보고서의 결론과 수치를 담지 않는다.** 연구질문, 방법의 구조, 답해야 할 항목, 기간만 담는다.

## 입력
- `reports/<id>/02_classification.json` (research_design: rq, methods, data, sample)
- `reports/<id>/03_argument_chains.json` (결론 목록: kind·statement·method·types — 결론의 **종류와 방법**만 참고하고 statement의 수치·판단은 옮기지 않는다)

## 출력
`reports/<id>/L2/blind_input/brief.md` — 아래 구조 그대로. 실제 예: `reports/R01/L2/blind_input/brief.md`

```
# 블라인드 재수행 브리프 · <id>
이 문서는 원 보고서의 결론을 담고 있지 않다. …
## 연구질문
(연구질문을 한 문단으로. "무엇을 예측·분석·제안하는가"만)
## 방법의 구조 (원 보고서와 같은 뼈대, 값은 스스로 정한다)
1. … (각 방법을 "무엇 × 무엇 = 무엇" 같은 구조로. 비율·성장률·단가 같은 파라미터 값은 절대 쓰지 않는다)
## 답해야 할 항목
- Q1 … (결론 하나당 질문 하나. 원 결론의 값·방향을 암시하는 표현 금지. "얼마인가", "어떻게 되는가", "무엇을 제시할 것인가"로 묻는다)
## 기간
현재 시점 <오늘>. 통계는 가장 최근 공식 발표치를 쓰고 기준 시점(asof)을 적는다.
```

## 규칙
- 수치, 연도별 값, 시나리오 값, 원 결론의 방향("증가할 것", "확대해야")을 쓰지 않는다. 방법의 파라미터 값(예: 채택률 3%)도 쓰지 않는다.
- 질문 수는 결론 수와 같거나 그보다 적다(RQ형 결론은 질문으로 만들지 않는다). 질문 ID `Q1…Qn`과 대응 결론 ID를 **별도 파일** `reports/<id>/L2/blind_input/question_map.json`(`{"Q1":"R01-K-Fc-06", …}`)에 적는다. 이 파일은 블라인드 에이전트에게 주지 않는다.
- 작성 후 스스로 검사: 브리프에 숫자(연도·기간 제외)가 있으면 지운다.
